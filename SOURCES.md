# Image sources

The retained source inventory contains **632 distinct artwork metadata records**. The initial source-filtered viewing pool contains **391 eligible paintings**: 366 Cleveland, 8 Met and 17 Chicago works with credited Wikimedia alternatives or bundled images. The other 241 records use the disabled Chicago IIIF image source and remain only in the metadata inventory; they do not appear in playback or the Artist list. It includes a new snapshot of **624** museum records (258 Chicago and 366 Cleveland), overlapping the original 57-record selection listed below. Nine JPEGs are bundled; all other images load on demand. Source URLs and metadata were checked on 22 October 2026. Bundled JPEG dimensions were measured from the files; other dimensions come from museum or Wikimedia image metadata.

The expanded inventory is stored in `museum-seed.js`, including each artwork's source-page URL, museum identifier, public-domain/CC0 designation, numeric date range, image dimensions and available subjects/styles. It contains metadata only. Chicago records were obtained from pages 1–3 of the official artwork search using public-domain, painting, image and latest-date-through-1900 filters; 258 of 300 records passed the quality/proportion checks. Cleveland records came from offsets 0–399 with CC0, Painting, image and pre-1901 filters; 366 of 400 passed the same checks and direct-image size limits. No additional JPEGs were downloaded into the package. [Chicago API](https://api.artic.edu/docs/), [Cleveland API](https://openaccess-api.clevelandart.org/).

Live discovery through the Met and Cleveland metadata APIs extends this inventory without a code update, and their new matching works can enter the viewing pool automatically. Chicago keeps its retained metadata snapshot and 17 curated works with credited Wikimedia alternatives or bundled images. Live Chicago discovery is disabled because new records point to the blocked Art Institute image hosts. The same filter applies to starter records, cached and fresh metadata, and restored history. Rights flags and image suitability are checked for newly obtained records; availability and museum classifications can change. The original selection's individual links below remain useful for the nine bundled images and established fallbacks.

The Met's designated Open Access images use CC0. Wikimedia file pages document their individual public-domain status; the Seurat reproduction has a PD-Art / Public Domain Mark notice. Cleveland's selected records have **share_license_status: CC0**. These are source-specific rights statements, with the limits explained in [IMAGE-RIGHTS.md](IMAGE-RIGHTS.md) for the nine bundled JPEGs. [Met image policy](https://www.metmuseum.org/policies/image-resources), [Cleveland Open Access policy](https://www.clevelandart.org/open-access).

## Bundling, discovery, and image handling

Bundled Seurat fallback: 3840 × 2556. Eight Met JPEGs are bundled at their original dimensions. Their per-file hashes and rights evidence are in [IMAGE-RIGHTS.md](IMAGE-RIGHTS.md).

The Met and Cleveland APIs refresh metadata on startup, after filter changes, daily and when browsing needs another page. Chicago uses its retained metadata snapshot without live discovery. The shared museum cache retains at most 2000 records and 12 recent queries, with at most 400 result identifiers per query and two concurrent museum requests. Records may overlap the starter catalogue. Date selection stays within works through 1900; source public-domain/CC0 checks apply per artwork. Availability and metadata can change.

The Met/Wikimedia image download path checks byte size and image headers before decoding, can resize supported images, and caches up to eight images / 160 MiB in IndexedDB. When a source fails, the gallery tries another matching painting automatically, up to six actual image attempts and an approximately 30-second soft deadline checked between attempts. Unavailable works and blocked hosts are temporarily skipped using a 160-entry failure registry; exposed Retry-After values are respected up to ten minutes.

Cleveland's CDN supports direct image display but does not provide the CORS header needed for fetch/Blob access. Its print JPEGs use a separate path: API dimensions and reported file size are checked before loading, followed by a natural-dimension check after decoding and before display. This path has no byte/header preflight, resizing, or IndexedDB image cache. The host's ordinary image cache controls reuse.

User-selected folders are separate local collections; their pictures use the host decoder and are outside the remote byte/header checks. They are not included in this public source inventory. See [README.md](README.md) for the nine Collection choices and three folder settings, and [PUBLISHING.md](PUBLISHING.md) before preparing a Workshop upload.

Museum collections and future discoveries can include classical artistic nudity. Select an appropriate Workshop age rating and an all-ages preview. [Official publishing guidance](https://docs.wallpaperengine.io/en/scene/first/publishing.html).

APIs: [The Met](https://metmuseum.github.io/), [Art Institute](https://api.artic.edu/docs/), [Cleveland](https://openaccess-api.clevelandart.org/), [Wikimedia imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo).

The wallpaper is an independent project, not an official museum product.
